# PLUTO panel（普鲁托面板）

![PLUTO panel](assets/banner.png)

> **插件标识**：`astrbot_plugin_token_panel`（保持不变，旧用户配置可直接复用）
> **版本**：v1.3.1 ｜ **作者**：Charon ｜ **协议**：MIT ｜ **适配**：AstrBot ≥ 4.11.4

PLUTO panel 是一个给 AstrBot 用的「上下文管家」：它把每个会话的 Token 用量变成看得见、管得住的东西，并且把上下文统计、压缩、承接这三件平时要靠指令才能做的事，全部收进一个后台面板里。

一句话概括它解决的问题：**你的机器人聊到一半时，究竟是快撑爆窗口了，还是才用了一点点？**

---

## 一、这是什么

AstrBot 会把每次请求的 token 用量记在会话表里，但没有一个地方能让你一眼看完「这个模型窗口多大、这个会话用了多少、还剩多少余量」。PLUTO panel 做了三件事：

1. **看得见**：后台「扩展功能 → PLUTO panel」里，按私聊 / 群聊分组列出所有会话，给出模型窗口上限、已用、剩余、占用百分比和彩色进度条。
2. **管得住**：到 80% 黄色提醒、95% 红色高危；跨阈值时可自动在 QQ 里播报一次（带节流，不刷屏）；也可以在面板里直接清空某个会话。
3. **能收拾**：内置 `/ctx_compress`（把旧历史压成一段摘要，会话 ID 不变）和 `/ctx_continue`（另开一个新会话接上，旧会话原样保留），压缩前自动备份、压缩后写日志。

所有数字都来自 AstrBot 自己的会话表与 Provider 配置，**不调用任何外部接口、不联网、不自己估算窗口**（唯一例外是压缩日志里的 token，那是插件内部的估算值，见第十节）。

## 二、功能清单

### 1. 后台面板（5 个标签）

| 标签 | 内容 |
| --- | --- |
| 通用设置 | 默认窗口上限兜底值、播报开关、调试日志开关 |
| 外观设置 | 主题风格（Claude Code / DeepSeek）、画布（象牙白 / 吸黑）、页面缩放、悬浮提示开关 |
| 数据面板 | 会话列表（私聊 / 群聊分组）、进度条、查看统计、压缩上下文、生成承接摘要、清空上下文、清理闲置网页会话 |
| 预警设置 | 预警阈值、高危阈值、播报冷却、播报格式预览 |
| 压缩承接 | 估算窗口、自动压缩、触发线、保留轮数、摘要字数、增强摘要、压缩日志（可筛选、可看备份、可跳转承接会话） |

- 进度条状态色：正常深灰、预警黄色、高危红色。
- 模型未配置窗口上限时，显示「该模型未设置窗口上限，无法计算占比」，不报错。
- 设置持久化在 `data/plugin_data/astrbot_plugin_token_panel/settings.json`，刷新页面不丢。

### 2. 网页会话的两种名字

网页面板里的会话没有 QQ 号可看，所以支持两种标识：

- **手动备注**：在网页聊天里发 `#标题 复习计划`，当前会话就改名「复习计划」；再发 `#标题` 清除。
- **AI 摘要**：没设备注时，点「重新读取」会用当前模型读最近几轮对话，生成一句 ≤20 字的摘要（有缓存，按新消息刷新；失败显示「摘要获取失败」，10 分钟内不重试）。

列表里显示为 `PLUTO│复习计划│a1b2c3d4` 或 `PLUTO│摘要：在问压缩规则│a1b2c3d4`，末段是会话短 ID。

### 3. QQ 指令

见第三节表格。全部指令都有独立前缀，不会占用 AstrBot 或其它插件的命令名。

### 4. 预警与播报

- 阈值默认 80% / 95%，可在面板或 `/token_ctxset` 修改。
- 只在「对话交互、调用指令」时刷新，不高频轮询。
- 自动播报只在**跨过阈值的那一次**推送一条，同一会话 30 分钟内不重复；正常聊天不会被插入任何插件提示。

### 5. 权限与容错

- `/token_ctx`、`/ctx`、`/ctx_sessions` 等只读指令所有人可用；会改写会话的指令仅管理员。
- 面板只对后台管理员开放；QQ 私聊会话按 `admins_id` 过滤，管理员看不到别人的私聊。
- 所有 token 读取都包在 try 里：读取失败只在面板显示「读取 Token 数据失败」，不抛异常、不阻塞消息主线程。

## 三、指令列表

### Token 面板

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/token_ctx` | 所有人 | 查看当前会话的 Token 进度卡片 |
| `/token_ctxon` | 管理员 | 开启自动进度播报 |
| `/token_ctxoff` | 管理员 | 关闭自动进度播报 |
| `/token_ctxset <百分比>` | 管理员 | 修改预警阈值（30–95） |
| `/token_clearctx` | 管理员 | 清空当前会话上下文（需二次确认） |

### 上下文统计 / 压缩 / 承接

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/ctx` | 所有人 | 查看当前会话的模型窗口上限、已用、占比 |
| `/ctx_compress [轮数]` | 管理员 | 把较早历史压成摘要，保留最近 N 轮，会话 ID 不变 |
| `/ctx_continue` | 管理员 | 用一段覆盖全部历史的摘要另开新会话并切换过去 |
| `/ctx_sessions` | 所有人 | 列出当前用户最近的会话，标注普通 / 承接派生 |
| `/ctx_switch <ID前缀>` | 管理员 | 按 ID 前缀切换回某个会话 |
| `/ctx_auto on\|off [阈值]` | 管理员 | 开关请求内自动压缩，并回显当前配置 |

### 仅网页聊天

| 指令 | 说明 |
| --- | --- |
| `#标题 名称` | 给当前网页会话设置备注（不调用模型） |
| `#标题` | 清除备注 |

> 指令名、权限、别名与 v1.3.0 完全一致，升级不改变使用习惯。

## 四、数据来源与口径

| 数据 | 来源 |
| --- | --- |
| 会话列表、标题、消息条数、最近更新时间 | `conversations` 表（AstrBot 官方会话表） |
| 已用 Token | `conversations.token_usage`（最近一次请求的总 token 快照） |
| `/ctx` 的「已用」 | `provider_stats` 表里该会话最近一条 `agent_type=internal` 记录（`token_input_cached + token_input_other`） |
| 模型窗口上限 | Provider 配置的 `max_context_tokens` → AstrBot 内置 models.dev 元数据 → 都没有则「未设置上限」 |
| 压缩日志里的 token | 插件内部**估算值**（中文 ×0.6、其它 ×0.3、每条消息 +4，逐条取整后求和） |

**面板上的「已用 Token」是上下文快照，不是账单。** 累计消费请去模型服务商后台看。

## 五、安装

### 方式一：插件市场（推荐）

1. 打开 AstrBot 后台 → 插件市场，搜索 PLUTO panel（或上传 zip）。
2. 点安装，装完在「插件管理」里启用。
3. 重载插件或重启 AstrBot，左侧「扩展功能」会出现 PLUTO panel 入口。

> 市场里的 zip 包根目录必须是 `astrbot_plugin_token_panel/`，不能外面再套一层文件夹。

### 方式二：手动安装

1. 把整个 `astrbot_plugin_token_panel` 文件夹放进 `AstrBot/data/plugins/`。
2. 后台 → 插件管理 → 重载插件（或重启 AstrBot）。
3. 确认日志出现 `[token_panel] 1.3.1 初始化完成` 与 `面板接口注册完成`。
4. 左侧「扩展功能 → PLUTO panel」即可打开面板。

### 从旧版本升级

- **1.2.x → 1.3.0+**：启动时自动禁用「上下文统计」和「上下文压缩和承接」两个旧插件（只禁用、不删文件），日志有提示。旧中文指令 `/上下文`、`/压缩` 等统一改为 `/ctx_*`，请改用新指令。
- **1.3.0 → 1.3.1**：直接覆盖文件、重载即可。配置只新增 `carry.enhanced_summary` 一个键，缺省关闭，行为与 1.3.0 完全一致，**不需要重置任何设置**。

## 六、冲突警告

- ⚠️ **不要同时启用 `astrbot_plugin_ctx_stats`（上下文统计）或 `astrbot_plugin_ctx_carry`（上下文压缩和承接）**。它们的指令已被本插件内置，同时开启会重复注册 `/ctx` 之类的命令。1.3.0+ 启动时会自动禁用它们；如果你手动又打开，请自行承担指令冲突。
- ⚠️ 其它「Token 统计」类插件与本插件功能重叠，建议只留一个，避免面板里出现两套数字。
- ⚠️ 修改 `max_context_tokens` 属于 AstrBot 侧配置，插件只读取、不修改。

## 十、压缩与承接规则速查

**压缩（`/ctx_compress`）**：取历史 → 按 `role=user` 切轮 → 旧段交给当前模型写摘要（≤500 字）→ 备份全文 → 用「摘要 + 最近 N 轮」重写历史 → 写压缩日志。**会话 ID 不变**。

**承接（`/ctx_continue`）**：把全部历史压成一段摘要 → 备份 → 新建会话（摘要 + 最近 4 轮）→ 自动切换过去 → 新会话继承父会话的备注与摘要。**旧会话原样保留**，可随时 `/ctx_switch` 切回。

**请求内自动压缩**：仅当「当前会话 ≥8 条消息」且「估算用量 ≥ 窗口 × 触发线」时触发，只替换本次请求发给模型的历史，**不写库、不改会话、不影响 `token_usage`**。

**备份与日志**：

- 备份：`data/plugin_data/astrbot_plugin_token_panel/carry_backups/<umo>/<会话ID前8位>-<时间戳>.json`，单会话最多 20 份，超出自动删最旧。
- 日志：`compress_log.json`，最多 200 条；记录类型、前后估算 token、保留轮数、备份文件名。
- 备份失败不影响压缩/承接本身，但日志行会标红，QQ 回复里也会提示。

**估算公式**：中文字符 ×0.6 + 其它字符 ×0.3 + 每条消息 4（结构开销），单条消息分别取整后求和。这是**估算**，与面板上的官方 token 是两套数字。

## 十一、排查

| 现象 | 处理 |
| --- | --- |
| 面板显示「未连接到 AstrBot 后台」 | 直接双击 html 打开会这样，请从后台「扩展功能 → PLUTO panel」进入 |
| 面板显示「读取 Token 数据失败」 | 打开插件调试日志，看 `[token_panel]` 开头的报错；通常是数据库读取问题 |
| `/ctx` 显示「获取模型上限失败」 | 当前 Provider 没有 `max_context_tokens`，元数据里也没有该模型；不影响聊天 |
| 面板没有入口 | 确认插件已启用、AstrBot ≥ 4.11.4，并重载插件 |
| 压缩后机器人「失忆」 | 摘要只保留要点，细节会丢；重要对话请用 `/ctx_continue` 而不是压缩 |
| 备份目录越来越大 | 单会话严格保留 20 份，正常不会膨胀；可手动清理 `carry_backups` |

## 十二、卸载

1. 后台 → 插件管理 → 停用并删除插件。
2. 删除 `AstrBot/data/plugin_data/astrbot_plugin_token_panel/`（含 settings、session_meta、compress_log、carry_backups）。
3. 删除 `AstrBot/data/plugins/astrbot_plugin_token_panel/`。
4. 重启 AstrBot。

卸载不影响聊天记录本身（会话数据在 `data/data_v4.db` 里，属于 AstrBot 核心）。

## 十四、FAQ

**Q：面板里的数字和 DeepSeek 后台账单对不上？**
A：「已用 Token」取的是 AstrBot 记录的最近一次请求总 token（`conversations.token_usage`），是**上下文快照**，不是累计账单。累计消费去模型服务商后台看。

**Q：为什么同一个会话的占用会突然变小？**
A：压缩/承接/清空都会改写上下文。压缩保留最近 N 轮 + 一段摘要；承接是新建会话从 0 开始；清空则归零。

**Q：`/ctx` 显示「获取模型上限失败」怎么办？**
A：说明当前 Provider 没配 `max_context_tokens`，AstrBot 元数据里也没有该模型。面板会显示「该模型未设置窗口上限，无法计算占比」，不报错，也不影响聊天。

**Q：压缩会丢聊天记录吗？**
A：会改写较早的历史，所以压缩前先备份全文（`carry_backups/`），并在日志里留档。想彻底不丢，用承接：旧会话原样保留。

**Q：`/ctx_auto on` 之后聊天记录会被改吗？**
A：不会。请求内自动压缩只替换**本次请求**发给模型的上下文，不写库、不改会话记录，也不影响 `token_usage`。

**Q：为什么 `/ctx_compress`、`/ctx_continue` 只有管理员能用？**
A：它们会改写或重建会话，属于破坏性操作；`/ctx`、`/ctx_sessions` 是只读，所有人可用。

**Q：网页会话的「摘要获取中…」一直不消失？**
A：摘要由当前模型生成，有 12 秒超时。失败会显示「摘要获取失败」，10 分钟内不再重试；检查 Provider 是否可用。

**Q：`#标题` 发出去机器人没反应？**
A：这是网页聊天专用指令，仅在面板会话里生效；它不会调用模型，也不会污染对话上下文。

**Q：升级后旧插件还开着，会不会重复响应？**
A：1.3.0+ 启动时会自动禁用「上下文统计」「上下文压缩和承接」，只禁用不删文件；日志里有提示。

**Q：面板显示「未连接到 AstrBot 后台」？**
A：直接双击 html 打开时会这样。请从后台「扩展功能 → PLUTO panel」进入，面板需要后台注入的桥接脚本。

**Q：备份目录会无限增长吗？**
A：不会。单会话严格保留最近 20 份，超出自动删最旧；日志保留 200 条。

**Q：压缩日志里的 token 和面板显示的 token 为什么不一样？**
A：日志里是压缩/承接时的**估算值**（中文 0.6 字、其它 0.3、每条 +4），面板里是 AstrBot 记录的**官方值**。两者口径不同，不要逐位对比。

**Q：1.3.1 的增强摘要和默认摘要有什么区别？**
A：默认摘要只记约定、称呼、偏好、进度、情绪、梗；增强摘要在此之上额外抽取关键数据、配置项与代码要点。默认关闭，行为与旧版完全一致。

**Q：「📌承接自」标签点不动 / 找不到会话？**
A：说明父会话已被清空或删除。标签只做定位跳转，不会重建数据。

**Q：备份写入失败会怎样？**
A：压缩/承接照常完成，但日志行会标红「备份失败」，QQ 回复里也会提示。建议检查 `carry_backups` 目录权限与磁盘空间。

**Q：v1.3.1 需要重置配置吗？**
A：不需要。v1.3.0 的 `settings.json` 可直接复用，只多一个默认关闭的 `carry.enhanced_summary`。

**Q：从插件市场更新后，旧指令 `/上下文` 还能用吗？**
A：不能。1.3.0 起统一为 `/ctx_*` 前缀，旧名已移除，请照第三节的表格换用新指令。

**Q：插件会访问外网 / 上传聊天记录吗？**
A：不会。所有数据来自本地 AstrBot 数据库，唯一的外部调用是「让当前模型生成摘要」，走的是你自己配置的 Provider。

**Q：为什么有些会话显示「尚无对话」？**
A：新建的网页会话在发出第一条消息前没有历史，压缩与统计都无从谈起；发一条消息后刷新即可。

**Q：SnowLuma / NapCat 适配器会影响插件吗？**
A：不影响。插件读的是 AstrBot 的会话表与 Provider，与消息从哪个适配器进来无关；指令按 umo 定位会话，换适配器后仍是同一个会话。
