> 版本：1.5.0 → 1.5.1（2026-10-29）

## 一、这次改了什么

一句话：**`/dy_log` 从「念三条标题」变成「让模型拿着真实记录说话」，并补了内存缓冲与自然语言入口。**

### 1. 新增「最近浏览」内存缓冲（20 条）

浏览结束时不只写落盘日志，还往内存里塞一份精简记录，只留标题、时长、时间、停留，供模型拼上下文用。

| 项目 | 规则 |
| --- | --- |
| 容量 | 20 条（`DY_RECENT_LIMIT`），超出丢弃最旧的 |
| 顺序 | 最新在前，编号 1 为最近一条 |
| 存储位置 | 进程内存 `self._dy_recent`，**重启即清空**，不写盘 |
| 落盘日志 | 完全不动：`data/douyin_log.json` 仍是 100 条上限，仪表盘 `/dy-log` 仍读它 |

### 2. `/dy_log` 改由模型作答

命令不再自己拼字符串，而是抛出一个模型请求，让模型用自己的语气念记录：

| 环节 | 处理 |
| --- | --- |
| 请求类型 | `ProviderRequest`，随 `yield` 交给 ProcessStage 的 agent 子阶段 |
| 人格 | 显式挂当前会话 `conversation`，人格提示词照常注入（不挂就等于跳过人格） |
| 提示词 | `_dy_llm_block()`：日志头 + 编号明细 + 5 条说话规则 |
| 记录为空 | 直接回纯文本「还没记录」，不浪费一次模型调用 |
| 模型异常 | 捕获后回退为纯文本列表，绝不静默失败 |

### 3. 自然语言也能问（新增 `on_llm_request` 钩子）

主人在聊天里顺口问「刚才刷了些什么」，不再需要敲命令：

| 判断点 | 规则 |
| --- | --- |
| 生效范围 | 仅 `event.is_admin()`（主人） |
| 触发条件 | `DY_ASK_RES` 六条正则命中：要求「刷/看/浏览」类词与「什么/哪些/记录」类词同时出现 |
| 排除项 | 以 `/` 开头的命令、超过 80 字的长文本、纯感叹（「这个视频挺好看的」「晚安」不触发） |
| 作用方式 | 把 `_dy_llm_block()` 追加进 `req.system_prompt`；已经拼过则跳过，不重复灌 |

### 4. 提示词里的硬约束

- 只许用给出的记录，**不许编造**标题、时长、时间，没有就说没有；
- 说人话、口语化，不罗列 JSON、不输出字段名；
- 明细默认最多列 10 条，讲重点即可。

## 二、为什么这样做（AstrBot 4.29.3 的机制）

- 命令处理器执行完，如果既没有 `stop_event` 也没塞 `provider_request`，**不会**顺带触发模型（`agent_sub_stages/internal.py` 有硬闸），所以老版 `/dy_log` 只能自己拼文本。
- 让命令走模型的正路是 `yield ProviderRequest(...)`：`process_stage/stage.py` 会识别并转交给 agent 子阶段；且管线是洋葱递归，agent 出结果时 RespondStage 已经发出去了，不会被后面的 `clear_result()` 清掉。
- 自然语言触发挂在 `@filter.on_llm_request()` 上（请求发出前、任何 provider 调用之前），比在每个入口埋钩子更稳。

## 四、怎么用

```
/dy_log                     # 模型用记录汇报
/dy_log 只看今天的            # 带个限定，模型会照办
刚才刷了些什么？              # 自然语言，主人限定，守卫命中即注入记录
```

## 五、兼容性与代价

- 落盘日志、仪表盘 `/dy-log`、风控调速、自动浏览节奏**均未改动**，属于纯增量。
- `/dy_log` 现在会消耗一次模型调用（老版是零成本纯文本）；记录为空时不调用。
- 内存缓冲随进程消失，重启后新问「最近刷了什么」会按「本进程内还没记录」回答，落盘日志仍在（`/dy-log` 接口可查）。
- 自然语言注入只在主人发言时发生，且要求命中问法正则，日常闲聊不会把日志塞进上下文。
