# 更新说明 v1.5.5

**一句话：修好滑杆的蓝色填充条。**

## 一、问题

拖动「预警阈值」滑杆时，圆点会走，但蓝色填充条停在上一次的值上不动；用数字框改成 88 之后，圆点已经到 88，填充条还停在 80，两者明显错位（`--fill` 变量没有跟随 `value` 更新）。

## 二、原因

填充比例靠 CSS 变量 `--fill` 驱动（轨道渐变 `var(--accent) 0 var(--fill), var(--track) var(--fill) 100%`），而 `--fill` 只在 `syncRange()` 里写入。`syncRange()` 只在初始化（`applySettings`）和缩放滑杆（`applyZoom`）时被调用过，阈值滑杆在拖动、数字框输入这两条路径上都漏了：

- `setWarn()` 只改了 `#warn-range` 与 `#warn-number` 的 value，没有重算 `--fill`。
- `loadRisk()` 回填严格系数时同样只写 value。
- `#risk-range` 从一开始就没有赋值 `--fill`，等于一直用默认的 50%。

## 三、修法

| 改动 | 位置 | 说明 |
| --- | --- | --- |
| 新增 `bindRanges()` | `syncRange()` 之后 | 启动时给页面上所有 `input[type="range"]` 按当前值算一次 `--fill`，并挂 `input` 监听持续同步；以后新加滑杆也自动生效 |
| `boot()` 调用 | `applySettings(state.settings)` 之后 | 在设置应用完之后执行一次 |
| `setWarn()` 补 `syncRange($("warn-range"))` | 阈值输入路径 | 数字框改值时填充条同步 |
| `loadRisk()` 补 `syncRange(range)` | 风控页回填路径 | 轮询刷新时填充条同步 |

顺带把滑杆行的「%」收紧：`.row .control > input[type="number"] + .value { min-width: 0; text-align: left; }`。原来这个 `%` 继承了 `.value` 的 44px 最小宽度并右对齐，数字框和它之间空出约 34px，像是断开的；现在紧贴数字框，整行右边界仍与下面「95%」「30 分钟」对齐。

## 四、未改动的部分

- 滑杆的取值范围、步长、默认值、保存/防抖逻辑、接口字段。
- 其余卡片、字号、间距、配色、图标与动效。

## 五、验证

- 连续改值 80 → 84 → 88 → 72 → 90，`--fill` 依次为 `66.7% / 75.6% / 84.4% / 48.9% / 88.9%`，与圆点位置一致。
- 风控严格系数 `1.0`（min 0.1 / max 2.0）→ `--fill: 47.4%`；缩放 `100`（80–140）→ `33.3%`。
- 滑杆行控制区宽度由 310px 收到 276px，「%」宽 9.8px，右边缘与下方数值列齐平。
- `consoleErrors` 为空。
