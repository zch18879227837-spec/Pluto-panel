# PLUTO panel（普鲁托面板）

![PLUTO panel](assets/banner.png)

> **插件标识**：`astrbot_plugin_token_panel`（保持不变，旧用户配置可直接复用）
> **版本**：v1.8.0 ｜ **作者**：Charon ｜ **协议**：MIT ｜ **适配**：AstrBot ≥ 4.11.4

PLUTO panel 是一个给 AstrBot 用的「上下文管家」：它把每个会话的 Token 用量变成看得见、管得住的东西，并且把上下文统计、压缩、承接这三件平时要靠指令才能做的事，全部收进一个后台面板里。

一句话概括它解决的问题：**你的机器人聊到一半时，究竟是快撑爆窗口了，还是才用了一点点？**

---

## 一、这是什么

AstrBot 会把每次请求的 token 用量记在会话表里，但没有一个地方能让你一眼看完「这个模型窗口多大、这个会话用了多少、还剩多少余量」。PLUTO panel 做了三件事：

1. **看得见**：后台「扩展功能 → PLUTO panel」里，按私聊 / 群聊分组列出所有会话，给出模型窗口上限、已用、剩余、占用百分比和彩色进度条。
2. **管得住**：到 80% 黄色提醒、95% 红色高危；跨阈值时可自动在 QQ 里播报一次（带节流，不刷屏）；也可以在面板里直接清空某个会话。
3. **能收拾**：内置 `/ctx_compress`（把旧历史压成一段摘要，会话 ID 不变）和 `/ctx_continue`（另开一个新会话接上，旧会话原样保留），压缩前自动备份、压缩后写日志。

这些数字全部取自 AstrBot 自己的会话表与 Provider 配置：不调用模型接口、不自己估算窗口（唯一例外是压缩日志里的 token，那是插件内部的估算值，见第十节）。插件里唯一会联网的是「抖音游客浏览」——独立 Playwright 子进程、只访问抖音精选页、结果只写本地 JSON，默认关闭；其余模块（Token 统计、压缩承接、主动消息、日记、搜索监控）都只读本地数据，不发起外部请求。

### 6b. 精细化主动消息（v1.4.1，默认关闭）

- 只在主人私聊里生效；群聊永不触发。
- 静默策略：主人发消息后静默 `reply_wait` 秒；主人连续发消息只计一次；主人 12 小时内说过话才进入候选。
- 情绪系统：`mood` 0~5 六级，每级决定下次最短间隔、每小时上限、每日上限与未回复次数上限。
- 未回复惩罚：连续未回复达到当前等级上限 → 等级 +1，冷却翻倍；主人回复后 24 小时无惩罚 → 等级 -1。
- 判断链路：模板档（本地，按情绪+时段随机） / 自适应档（模型判断该不该发、给内容）；失败回退模板档。
- 重复规避：与最近 15 条发言比对，相似度过高就换一句话。
- 每日配额：`daily_limit` 条（默认 6），QQ 文本类指令不自动宣读，所有变更由网页提示。

### 6c. 会话日记本（v1.6.0，默认关闭）

和压缩、承接并行的一套长期备忘，只记"值得长期记住的事"。

- 写入：每轮回复结束时，模型判断本轮有可记的事，会在回复末尾附 `<diary weight="high">…</diary>`；插件抠出正文与权重存进当天日记，再把标签从回复里剥掉，用户看不到。
- 篇数由模型定：按自然日计数，单日 1–3 篇（默认 3），没有够格的信息就 0 篇；同类内容重复出现会跳过。
- 检索：每轮对话前按当前提问做相似度打分，先权重（高 > 中 > 低）后相似度，只把最相关的 1–3 条注入系统提示，无关的不注入（不会整本塞进上下文）。
- 存储：`data/plugin_data/astrbot_plugin_token_panel/diary_log/{user_id}/{session_id}.json`，单会话不设总条数上限。
- 继承：`/ctx_continue` 承接时把日记复制到新会话，权重一并保留；`/ctx_clear`、面板清空、批量清理空/闲置会话时同步删除。
- 开关关闭后写入、检索、注入全部休眠，原有面板与聊天逻辑不受影响。

### 2. 网页会话的两种名字

网页面板里的会话没有 QQ 号可看，所以支持两种标识：

- **手动备注**：在网页聊天里发 `#标题 复习计划`，当前会话就改名「复习计划」；再发 `#标题` 清除。
- **AI 摘要**：没设备注时，点「重新读取」会用当前模型读最近几轮对话，生成一句 ≤20 字的摘要（有缓存，按新消息刷新；失败显示「摘要获取失败」，10 分钟内不重试）。

列表里显示为 `PLUTO│复习计划│a1b2c3d4` 或 `PLUTO│摘要：在问压缩规则│a1b2c3d4`，末段是会话短 ID。

### 3. QQ 指令

见第三节表格。全部指令都有独立前缀，不会占用 AstrBot 或其它插件的命令名。

### 4. 预警与播报

- 阈值默认 80% / 95%，可在面板或 `/token_ctxset` 修改。
- 只在「对话交互、调用指令」时刷新，不高频轮询。
- 自动播报只在**跨过阈值的那一次**推送一条，同一会话 30 分钟内不重复；正常聊天不会被插入任何插件提示。

### 5. 联网搜索（v1.9.0 内聚模块）

从 1.9.0 起，联网搜索不再依赖独立插件 `astrbot_plugin_websearch`——检索工具、配置、日志、面板页都在本插件里：

- **工具**：注册 `web_search`（DeepSeek 官方搜索接口），语义与独立版一致；**是否搜索、搜几次由模型人设决定**，插件只提供能力与上限；
- **替代原生**：启用模块时会把 AstrBot 自带的 `web_search` 工具关掉（`provider_settings.web_search=false`），避免两份结果打架；
- **日志**：每次检索把「时间 / 服务商 / 关键词 / 结果条数 / 耗时 / 成败」写进本地 `websearch/search_log.db`，只记元数据、不存网页正文；
- **面板「联网搜索」页**：模块总开关、服务商、API Key（打码显示，留空即不改）、搜索次数上限、超时、默认返回条数、是否允许回复带链接；下方是搜索概况与可筛选的搜索记录，支持清空日志；
- **模块隔离**：关掉模块时工具立即注销、独立版插件自动恢复；再打开则反向同步。两套开关始终只有一方生效，不会重复注册工具。

**搜索时机由人设决定（v1.10.0）**

- 工具的 `description` 里写了「什么时候用 / 什么时候不用 / 一个问题最多两轮 / 别把链接整段甩出来」；
- 人设（`personas` 表里「大肥鱼」的 `system_prompt`）里也有一节「▌上网搜索规则（web_search）」，用它自己的口吻写明该搜与不该搜的场景、查不到怎么说；
- 两处是同一套规则的两层兜底：模型看人设决定要不要搜，真要调用时再读工具说明确认参数——不需要你手动教它什么时候上网。

旧数据会自动迁移：首次启用时若检测到独立版的历史日志库，会按 `ts` 去重后并入新库（旧库原样保留）。

### 6. 抖音游客浏览

用独立浏览器以**未登录游客**身份打开抖音精选页，滚动看视频并记录标题，用来模拟真人刷抖音：

- 只打开精选页：不登录、不点赞、不评论、不搜索（搜索页会触发图形验证码，已主动避开）；
- 每次浏览有「单次时长 + 单次视频数」双上限，先到先停；每天还有次数上限，可设免打扰时段；
- 遇到安全验证（图形验证码）立即停止并通知，不会硬闯；
- 看完把标题汇总成**一条** QQ 消息发给管理员，可以关掉。

> 浏览器跑在独立子进程里（`worker/douyin_worker.py`），崩溃或卡死都不会影响机器人收发消息。

### 8. 抖音风控调速（v1.5.0）

抖音标签页只展示「看了什么」，真正的防护参数放在这一页自动调，你不用记公式：

- **严格系数**（0.1–2.0，默认 1.0）：整页唯一需要你动手的东西。系数越大，同样一次验证会更快压到低档位，恢复也更慢；调小则更激进、回升更快。
- **三档位自动降档**：
  - 正常：单次 8 个视频 / 8 分钟 / 间隔 180 分钟 / 停留 8–20 秒；
  - 轻度降档：6 个 / 6 分钟 / 间隔 288 分钟 / 停留 12–26 秒；
  - 深度降档：3 个 / 4 分钟 / 间隔 396 分钟 / 停留 16–32 秒。
- **分数怎么算**：近 3 天内的每次安全验证按「24 小时半衰期」加权计入（单次最严 2.0 封顶），分数 >0.8 轻度、>2.0 深度；最后一次验证 90 分钟后进入回升期，再 90 分钟平滑复原。
- **实时状态只读**：当前档位、风控分数、当前阶段（正常运行 / 冷却中 / 回升中）、最近一次验证、回升进度条。只在页面停留时每 5 秒拉一次，切走即停。
- **手动 `/dy_set` 优先**：手动设的参数 2 小时内优先于自动降档，时间到自动交还给算法。
- 单视频停留有 **8 秒硬底线**，任何档位都不破。

### 9. 详细推理完成通知（v1.7.0，默认开启）

整轮推理彻底结束后**发一条**汇总通知，流式过程中绝不插话；中断的请求单独发失败通知。

- 内容：模型名、推理耗时、输入/输出/总 Token、记忆写入状态、联网与抖音调用、风控等级；三项均可单独关闭。
- 投递：仅原会话（默认）/ 仅管理员私聊 / 双推送，发往 QQ 的条目会忽略群聊。
- 额外：自定义成功/失败前缀、管理员 QQ 列表、可选语音播报（复用 AstrBot 现有 TTS 提供商，无 TTS 时自动跳过）。
- 数据：`plugin_data/astrbot_plugin_token_panel/notify_log.json`，面板可查看与清空。

### 10. 语音合成 TTS（v1.7.1，默认关闭）

把回复文本交给 AstrBot **原生 TTS 提供商**合成语音，与文字一起发出；不新增任何外部接口。

- 三种触发：①全局开关打开后按私聊/群聊开关自动带语音；②消息里出现「发语音 / 语音说 / 用语音回答」时**只对当轮**强制带语音（触发词不进模型上下文）；③指令、压缩承接等系统回复一律不合成，避免指令刷屏。
- 音色与语速：面板可填音色 ID、拖语速（0.5–2.0）；留空则沿用框架里该提供商当前配置。
- 长文本：超过 `max_chars`（默认 180 字）自动切段，最多 `max_segments`（默认 6）段；emoji 与非语音字符会被清洗，避免合成失败。
- 文字+语音：`send_both` 打开时文字与语音同时发送，关闭则只发语音。
- 统计：`plugin_data/astrbot_plugin_token_panel/tts_stats.json`（次数 / 段数 / 字数 / 最近时间），面板与 `/tts_status` 都能看。

### 7. 权限与容错

- `/token_ctx`、`/ctx`、`/ctx_sessions` 等只读指令所有人可用；会改写会话的指令仅管理员。
- 面板只对后台管理员开放；QQ 私聊会话按 `admins_id` 过滤，管理员看不到别人的私聊。
- 所有 token 读取都包在 try 里：读取失败只在面板显示「读取 Token 数据失败」，不抛异常、不阻塞消息主线程。

## 十、压缩与承接规则速查

**压缩（`/ctx_compress`）**：取历史 → 按 `role=user` 切轮 → 旧段交给当前模型写摘要（≤500 字）→ 备份全文 → 用「摘要 + 最近 N 轮」重写历史 → 写压缩日志。**会话 ID 不变**。

**承接（`/ctx_continue`）**：把全部历史压成一段摘要 → 备份 → 新建会话（摘要 + 最近 4 轮）→ 自动切换过去 → 新会话继承父会话的备注与摘要。**旧会话原样保留**，可随时 `/ctx_switch` 切回。

**请求内自动压缩**：仅当「当前会话 ≥8 条消息」且「估算用量 ≥ 窗口 × 触发线」时触发，只替换本次请求发给模型的历史，**不写库、不改会话、不影响 `token_usage`**。

**备份与日志**：

- 备份：`data/plugin_data/astrbot_plugin_token_panel/carry_backups/<umo>/<会话ID前8位>-<时间戳>.json`，单会话最多 20 份，超出自动删最旧。
- 日志：`compress_log.json`，最多 200 条；记录类型、前后估算 token、保留轮数、备份文件名。
- 备份失败不影响压缩/承接本身，但日志行会标红，QQ 回复里也会提示。

**估算公式**：中文字符 ×0.6 + 其它字符 ×0.3 + 每条消息 4（结构开销），单条消息分别取整后求和。这是**估算**，与面板上的官方 token 是两套数字。

## 十三、审计与已知依赖

> 对应 AstrBot 市场 v1.7.2 的审核建议（VirusTotal 与代码审查均已通过，0 恶意行为）。

**1）跨插件只读依赖（跨插件数据读）**
`notify.py` 生成“详细推理完成通知”时，会用 `sqlite3` 以 **只读模式（`mode=ro`）** 打开同级插件
`astrbot_plugin_livingmemory` 的数据库，只读取记忆条数用于展示。行为边界：

- 只读，不写入、不加锁、不修改对方数据；
- 对方插件不存在 / 数据库被占用 / 表结构变化时，`try/except` 兜底，通知照常发出，只是记忆条数显示为 `—`；
- 若你不想存在这种跨插件依赖，可在设置里关掉通知的“记忆状态”开关，或不安装 LivingMemory。

**2）自动化条款提醒（抖音游客浏览）**
该功能用独立的 Playwright 子进程以未登录游客身份浏览抖音精选页，并做了常规的自动化指纹隐藏。
它**默认关闭**，仅在你手动开启或 `/dy_test` 时运行，结果只写本地 JSON、不上传任何数据。
但仍请注意：自动化访问可能不符合目标站点的服务条款，请自行评估使用风险；建议保持低频（默认 3 小时一次、每日 3 次上限）。

**3）包体干净度**
插件目录不再包含 `__pycache__`、`dist` 打包产物与第三方遗留配置；市场 zip 由 `tools/pack.ps1` 生成，
只保留运行必需文件（`main.py` / `notify.py` / `proactive.py` / `risk_tuning.py` / `tts_module.py` / `websearch.py` /
`worker/` / `views/` / `assets/` / `metadata.yaml` / `plugin.json` / `_conf_schema.json` / `README.md` / `LICENSE`）。

- `/token_ctx` 进度卡片、`/token_ctxon`、`/token_ctxoff`、`/token_ctxset`、`/token_clearctx` 五条指令
- 预警 80% 黄 / 95% 红，跨阈值自动播报（节流防刷屏）
- 管理员会话隔离、异常降级、请求防抖

#### 🔧 兼容性

- 只读 AstrBot 官方会话表与 Provider 配置，不改核心
- 除抖音游客浏览外不联网：该功能默认关闭，开启后由独立子进程访问抖音，不读取任何第三方数据
- 不硬编码本机路径：搜索日志库位置、Playwright 浏览器目录都写成了可配置项，换机器能在面板里改

## 十五、FAQ

**Q：换了电脑 / 换了盘符，搜不到搜索日志、抖音也打不开浏览器？**

A：v1.6.3 起这两处不再写死路径。面板「设置」里填 `net_log_db`（websearch 插件的 `search_log.db` 路径）与 `playwright_browsers_path`（Playwright 浏览器目录），留空则自动探测。探测不到时搜索监控显示「读取搜索日志失败」，抖音浏览会在日志里给出 `db_found=false` 或浏览器路径错误。

**Q：为什么加了日记之后，DeepSeek 的缓存命中突然掉了一半？**

A：v1.6.3 之前是设计缺陷——每轮把相关日记拼进系统提示，前缀一变，前面所有 token 都按「非缓存输入」重新计费。现在规则文本固定、相关日记走临时内容块（不进历史、不改前缀），实测缓存命中恢复到 8704、非缓存输入只多 31。如果你看到 hit 突然掉，先确认插件版本是 1.6.3。

**Q：备份写失败会怎样？**

A：压缩/承接的备份写失败时，不会静默继续——QQ 提示、日志都会写清楚，面板「压缩日志」里对应那行会标红并带「⚠ 备份失败」标记。备份目录仍按会话保留最多 20 份，超出的自动删最旧。

**Q：面板里的数字和 DeepSeek 后台账单对不上？**
A：「已用 Token」取的是 AstrBot 记录的最近一次请求总 token（`conversations.token_usage`），是**上下文快照**，不是累计账单。累计消费去模型服务商后台看。

**Q：为什么同一个会话的占用会突然变小？**
A：压缩/承接/清空都会改写上下文。压缩保留最近 N 轮 + 一段摘要；承接是新建会话从 0 开始；清空则归零。

**Q：`/ctx` 显示「获取模型上限失败」怎么办？**
A：说明当前 Provider 没配 `max_context_tokens`，AstrBot 元数据里也没有该模型。面板会显示「该模型未设置窗口上限，无法计算占比」，不报错，也不影响聊天。

**Q：压缩会丢聊天记录吗？**
A：会改写较早的历史，所以压缩前先备份全文（`carry_backups/`），并在日志里留档。想彻底不丢，用承接：旧会话原样保留。

**Q：`/ctx_auto on` 之后聊天记录会被改吗？**
A：不会。请求内自动压缩只替换**本次请求**发给模型的上下文，不写库、不改会话记录，也不影响 `token_usage`。

**Q：为什么 `/ctx_compress`、`/ctx_continue` 只有管理员能用？**
A：它们会改写或重建会话，属于破坏性操作；`/ctx`、`/ctx_sessions` 是只读，所有人可用。

**Q：网页会话的「摘要获取中…」一直不消失？**
A：摘要由当前模型生成，有 12 秒超时。失败会显示「摘要获取失败」，10 分钟内不再重试；检查 Provider 是否可用。

**Q：`#标题` 发出去机器人没反应？**
A：这是网页聊天专用指令，仅在面板会话里生效；它不会调用模型，也不会污染对话上下文。

**Q：升级后旧插件还开着，会不会重复响应？**
A：1.3.0+ 启动时会自动禁用「上下文统计」「上下文压缩和承接」，只禁用不删文件；日志里有提示。

**Q：面板显示「未连接到 AstrBot 后台」？**
A：直接双击 html 打开时会这样。请从后台「扩展功能 → PLUTO panel」进入，面板需要后台注入的桥接脚本。

**Q：备份目录会无限增长吗？**
A：不会。单会话严格保留最近 20 份，超出自动删最旧；日志保留 200 条。

**Q：压缩日志里的 token 和面板显示的 token 为什么不一样？**
A：日志里是压缩/承接时的**估算值**（中文 0.6 字、其它 0.3、每条 +4），面板里是 AstrBot 记录的**官方值**。两者口径不同，不要逐位对比。

**Q：1.3.1 的增强摘要和默认摘要有什么区别？**
A：默认摘要只记约定、称呼、偏好、进度、情绪、梗；增强摘要在此之上额外抽取关键数据、配置项与代码要点。默认关闭，行为与旧版完全一致。

**Q：「📌承接自」标签点不动 / 找不到会话？**
A：说明父会话已被清空或删除。标签只做定位跳转，不会重建数据。

**Q：备份写入失败会怎样？**
A：压缩/承接照常完成，但日志行会标红「备份失败」，QQ 回复里也会提示。建议检查 `carry_backups` 目录权限与磁盘空间。

**Q：v1.3.1 需要重置配置吗？**
A：不需要。v1.3.0 的 `settings.json` 可直接复用，只多一个默认关闭的 `carry.enhanced_summary`。

**Q：从插件市场更新后，旧指令 `/上下文` 还能用吗？**
A：不能。1.3.0 起统一为 `/ctx_*` 前缀，旧名已移除，请照第三节的表格换用新指令。

**Q：插件会访问外网 / 上传聊天记录吗？**
A：不会。所有数据来自本地 AstrBot 数据库，唯一的外部调用是「让当前模型生成摘要」，走的是你自己配置的 Provider。

**Q：为什么有些会话显示「尚无对话」？**
A：新建的网页会话在发出第一条消息前没有历史，压缩与统计都无从谈起；发一条消息后刷新即可。

**Q：SnowLuma / NapCat 适配器会影响插件吗？**
A：不影响。插件读的是 AstrBot 的会话表与 Provider，与消息从哪个适配器进来无关；指令按 umo 定位会话，换适配器后仍是同一个会话。

**Q：点「清空上下文」没反应是怎么回事？（v1.3.2 已修）**
A：1.3.1 及更早用的是浏览器原生 `window.confirm`，插件页在后台 iframe 里运行时会被浏览器直接吞掉，确认框不出现、操作也就没执行。1.3.2 起改用插件内自绘确认框，点按钮会正常弹窗，确认后才清空。

**Q：清空之后会话行为什么还留着？怎么彻底删掉？**
A：清空只把上下文与 token 归零，会话行本身还在（会话 ID 不变，方便接着聊）。1.3.2 起这类行会标「空会话」，点数据面板顶部的「删除空会话」即可一次性收掉，删除前有确认框。

**Q：「删除空会话」会删掉 QQ 会话吗？**
A：只删「没有任何历史且 token 为 0」的会话行；QQ 私聊仍受管理员白名单约束，看不到的会话也不会被删。有历史的会话一律跳过。

**Q：抖音浏览会不会被判定为异常流量？**
A：不会登录、不会点赞评论，只以游客身份打开精选页滚动浏览；每次有单次时长与条数双上限、每天有次数上限、可设免打扰时段，遇到图形验证码会立刻停止并通知，不会硬闯。

**Q：抖音浏览为什么搜不了关键词？**
A：抖音的搜索结果页会触发图形验证码（点形状相同的物体），hard 闯容易被风控，所以本插件只走精选页。关键词过滤是对「看过的视频标题」做筛选，不是去抖音搜索。

**Q：抖音浏览需要额外装什么？**
A：需要 Playwright 的 Chromium（`pip install playwright` + `playwright install chromium`）。没装时面板与指令会提示「缺少依赖」，不影响其它功能。

**Q：联网搜索监控的数字是实时的吗？**
A：是 websearch 插件写入本地日志表后立刻可见；面板每次打开或点「过滤」才读一次，不做轮询。

**Q：清空搜索日志会删除 websearch 的搜索记录吗？**
A：只删本地日志表的行，不影响 websearch 的配置、API Key 和统计；下次搜索会继续写入新记录。

**Q：升级会不会影响我正在用的设置？**
A：不会。插件标识没变，`settings.json` 原样复用，新增的抖音配置项首次读取时自动补默认值（默认关闭）。

**Q：主动消息会不会自己开口？会不会打扰我？**
A：默认是关闭的。开启后也只在**主人私聊**里、且满足「你 12 小时内说过话 + 已过静默期 + 当前情绪等级允许 + 今日配额未满」才会发；群聊永不触发。每级情绪都有每小时/每日上限，连续没回复还会自动降级，越不理它越安静。

**Q：主动消息和 `astrbot_plugin_proactive_chat` 能一起开吗？**
A：不建议。两者都会定时给主人发消息，同时开启会收到双份。本插件已内置主动消息能力，装了旧插件请在后台把它关掉。

**Q：新版面板的配置都在哪？原来右上角的齿轮去哪了？**
A：v1.4.1 曾把配置收进右上角 ⚙ 抽屉，**v1.5.3 起抽屉已经取消**，全部配置改成左侧一级导航（当前 11 项）：上下文监控 / 搜索监控 / 抖音浏览 / 抖音风控调速 / 推理通知 / 行为 / 显示 / 主动消息 / 压缩承接 / 日记本 / 阈值与播报。所有旧配置项都在对应页里，取值不变，只是位置变了。

**Q：「自适应档」会不会乱说？**
A：不会。自适应档只让模型判断「此刻适不适合开口」，并给一句 40 字以内的内容，且要求「没有具体理由就返回 skip」；模型超时、报错、返回空都自动回退到本地模板档，最坏情况就是发一句安全的模板话。

**Q：主动消息的日志里那些「跳过」是什么意思？**
A：日志会记录跳过原因（静默中 / 未到间隔 / 每日上限 / 未回复上限 / 模型选择不开口 / 内容重复等），方便你判断它是不是太安静——觉得太克制就把情绪等级调回 0，或把最短间隔调小。

**Q：面板显示窗口上限 1,000,000，可我印象里是 128K，到底哪个对？**
A：插件按「手动填写 > Provider 的 `max_context_tokens` > 模型元数据」依次取值。AstrBot 在 Provider 没配上限时会把兜底值 `128000` 写回 Provider 配置，这个数字并不代表模型真实窗口，所以插件不会把它当成真实上限，会继续查模型元数据（`deepseek-flash` 为 1,000,000）。要强制用某个数字，在左侧「行为」页 → **上下文上限（手动兜底）**里填一次即可（`0` = 自动），所有会话立刻按它重算占比与剩余。

**Q：换了模型或改了上限，面板上的百分比没跟着变？**
A：点右上角「刷新数据」，或对某行点「查看统计」，都会重新解析上限并重算；不需要重载插件、也不会写库。

**Q：严格系数调到 2.0 有什么变化？**
A：只影响「触发验证之后的动作」——同样一次验证会更快压到低档位、恢复更慢。没触发验证时参数不变，仍然 8 个 / 8 分钟 / 180 分钟。

**Q：我把系数调了，为什么抖音参数还是 8 个？**
A：降档是「事件驱动」的，系数只是放大镜。想立刻收紧，用 `/dy_set videos 3` 这类手动设置，2 小时内优先于算法。

**Q：分数 0.00，但档位写着「轻度降档」？**
A：分数按 24 小时半衰期衰减，窗口内可能还有很小的残余分；页面保留两位小数会显示 0.00，档位按内部值判定，属正常。

**Q：滑块拖到 0.5 或 3 会怎样？**
A：严格系数只接受 0.1–2.0。越界、非数字都会被拒绝并给出提示，原值保持不变。

**Q：风控调速页会一直请求后台吗？**
A：只在页面停留时每 5 秒拉一次轻量的只读状态，切走立即停止；不轮询数据库，也不会触发浏览。

**Q：为什么我开了通知却没收到？**
A：①看 `mode`：`session` 只发给发起对话的会话；②群里发起的对话默认不向群聊投递，需打开 `group_enabled`；③面板里点「测试通知」可先验证链路。

**Q：语音播报没声音？**
A：插件只调用 AstrBot 已配置的 TTS 提供商；未配置或合成失败时会静默降级为纯文本，面板会显示「已检测到 TTS / 未检测到 TTS」。

**Q：通知会不会打断流式输出？**
A：不会。只在整轮彻底结束后发送一次；用户中断或被超时终止时发失败通知。

**Q：开了语音，为什么这次只来了文字？**
A：先确认全局开关与私聊/群聊开关；再看提供商是否可用（`/tts_status` 会显示「已检测到 TTS / 未检测到 TTS」）。合成失败会自动降级成纯文本，不会吞掉消息。

**Q：群里会不会被机器人刷屏语音？**
A：默认不会。群聊语音是独立开关，默认关闭；即使打开，指令回复和系统提示也不会合成。

**Q：「发语音」这个触发词会不会被模型看到？**
A：不会。触发词在处理阶段就被剥掉，只用来决定本轮是否附语音。

**Q：音色填了没反应？**
A：音色 ID 必须与提供商支持的音色一致（例如 DashScope 的 Cherry）；不确定就留空，用框架里已配置好的音色。

**Q：语音文件存在哪？**
A：插件只做合成与发送，不落盘音频；只把统计写进 `plugin_data/astrbot_plugin_token_panel/tts_stats.json`。

### 主题切换后有的地方颜色没变？

v1.8.0 起组件层只引用令牌，理论上不会出现。若确实遇到，多半是浏览器缓存了旧的 `index.html`：在面板页按 `Ctrl+F5` 强制刷新，或在后台「插件」里重载一次插件。

### 为什么只保留两套主题了？

v1.8.0 按视觉规范把「风格 × 明暗」的 4 种组合收敛为两套完整令牌集合（夜间吸黑 / 白色浅色）。旧配置里的 `theme=ink/ivory` 会自动映射，无需手动迁移。

### 右侧的「对话」栏是什么？

常驻的只读快照：列出最近 3–6 个会话的占用与快捷操作（统计 / 压缩 / 承接），方便边看数据边动手；它不写入任何数据，窄屏（<1180px）自动隐藏。

### 界面字号变大了，能改小吗？

正文最小 12px 是规范底线（可读性）。想整体缩放用外观页的「页面缩放」(85%–140%)，它只缩放面板内容，不影响后台其它页面。

### 为什么模型有时候还是不搜？

先确认三件事：①面板「联网搜索」页里模块是**开着**的、Key 状态是「已配置」；②人设里那段「▌上网搜索规则（web_search）」没有被别的插件改掉；③问题本身确实需要外部信息（纯闲聊不搜是设计如此）。
还不行就在「联网搜索」页点一次「测试检索」，能返回结果说明链路没问题，属于模型判断问题——可以在人设里把「该搜」的场景写得更具体。

### 想让「搜完带链接」怎么办？

面板「联网搜索」页打开「允许回复里带链接」，模型在需要来源时就会附上 URL；关掉时它只转述内容，不甩链接。

### 之前的 `astrbot_plugin_websearch` 还要留吗？

不用。1.9.0 起搜索能力已经内聚到本插件，启用「联网搜索」模块时独立版会被自动停用（文件不删，随时可回退）。
如果两边的日志都想看，独立版的历史记录会在首次启用时并入新库。

### 关掉搜索模块后，机器人还能上网吗？

看独立版插件状态：模块关闭时会把它恢复成你上次的样子（通常是被停用），所以默认情况下就没有联网能力了。
想彻底断网就保持两边都关，并在 AstrBot 的「配置文件 → AI → 工具」里确认 `web_search` 不在列表里。
