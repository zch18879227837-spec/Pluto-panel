# PLUTO panel v1.16.3 更新说明

> 发布日期：2026-10-31 ｜ 类型：插件市场审核整改（无功能变更）

## 这次改了什么

插件市场对 v1.16.2 的审核给了三条建议，全部是「发布包卫生」性质，功能一行没动。

### 1. 包里的垃圾文件

审核反馈包内混入了 `__pycache__/`、多个 `*.bak` 备份、以及 `dist/` 里 3 MB 的旧 zip，说明那次上传的包不是用打包脚本产出的。

处理：
- 插件目录清空：`__pycache__/`、7 个 `*.bak*`、`dist/*.zip` 全部移出插件目录、单独留档。
- `tools/pack.ps1` 的跳过列表补充 `node_modules`、`.pytest_cache`、`.mypy_cache`、`tests`。

### 2. 敏感文件（最重要）

审核在包里发现了 `data/cmd_config.json`——那是**作者本机 AstrBot 主配置的快照**，含 dashboard 密码哈希（pbkdf2/md5）、admin id、host 0.0.0.0 等信息。代码里没有任何地方读它，但发布包里出现就是泄露风险。

处理：
- 目录里已无 `data/`。
- `pack.ps1` 增加**硬性拦截**：打包完成后逐个检查 zip 条目，命中下面任意一条就直接失败退出，不再靠人眼确认——
  `__pycache__`、`*.pyc`、`*.bak*`、`data/`、`cmd_config.json`、`plugin_data/`、`douyin_captures/`、`*.db`、`*.log`、`*.jsonl`、`dist/`、`*.zip`、`settings.json`。
- `.gitignore` 同步补上 `dist/`、`*.bak*`、`__pycache__/`、`*.pyc`、`data/cmd_config.json`、`plugin_data/`、`douyin_captures/`。

### 3. GSAP 的 CDN 引用

面板里的 `loadGsap()` 原本会向 `cdn.jsdelivr.net` 拉 GSAP 3.12.5，而页面末尾其实**已经内联**了同一份源码，等于多了一个不必要的外部依赖。

处理：
- 删掉 CDN 那行，`loadGsap()` 改成只等内联脚本就绪；万一内联不可用，动效自动退回 WAAPI（原有降级逻辑不变）。
- 顺带删掉没有任何引用的 `assets/vendor/gsap.min.js` 副本，包体更小。
- 现在面板**零外部脚本请求**，断网 / 内网环境都能正常动效。

## 升级方式

1. 用新的 `pluto-panel-v1.16.3.zip` 重新上传（别再传旧包）。
2. 面板里点「重载插件」，或在后台插件页重载一次。
3. 页脚应显示 `PLUTO panel v1.16.3`。

## 兼容性

- 双主题、上下文监控与置顶、记忆、日记本、大肥鱼小屋、抖音 PC 操控等全部功能未改动。
- 数据结构、接口、指令均无变化，可直接覆盖升级。
