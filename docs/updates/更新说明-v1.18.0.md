# PLUTO panel v1.18.0 · 更新说明

发布日期：2026-11-02
主题：**抖音改网页版 + 公共风控 + 双平台会话**

## 这次换掉了什么

旧方案是「操控本机抖音 PC 客户端 + 截图 OCR 认按钮」，问题很实在：窗口一被挡住就瞎、客户端升级就认不出控件、还得要求抖音以普通权限运行。

现在改成 **Playwright 打开抖音网页**：

- 扫码登录一次，cookie 留在 `douyin_profile/`；
- 私信轮询接进 AstrBot 事件流 —— 也就是说抖音来的消息和你 QQ 消息走同一套管线：人设、指令、权限、TTS、记忆、日记、小屋全部复用；
- 回复只回到发消息的那一边，不会 QQ、抖音同时发。

## 新增能力

| 指令 | 干什么 |
| --- | --- |
| `/douyin_start` | 开始自动下滑刷视频（按风控节奏，不是死循环） |
| `/douyin_stop` | 停下 |
| `/douyin_like` | 给当前视频点赞 |
| `/douyin_comment <文本>` | 对当前视频发评论 |
| `/douyin_share` | 把当前视频分享到私信（带一句贴合人设的感想） |

刷视频、点赞、评论、私信发送，**执行前都会先问公共风控**；被限流就等冷却，并在事件日志里留一条「限流」。

## 公共风控

`risk_core.py` 是这一版抽出来的公共核心：60 秒滑动窗口、按「平台 + 用户 + 动作」分桶、触限冷却、随机延时、告警事件。抖音和 QQ 各算各的。

面板「抖音浏览 → 自定义行为风控」可以直接改：

- 每分钟切视频 / 点赞 / 评论 / 私信回复上限
- 动作随机延时（最小 ~ 最大秒）
- 触限冷却秒数
- 单次会话动作上限（0 = 不限）

**没有内置封顶，参数由你定。** 唯一的硬底线是私信轮询间隔 ≥ 5 秒，防止轮询太密把 cookie 弄丢。
参数激进带来的账号风控、封号风险，需要你自己权衡。

## 双平台怎么处理

- 身份：QQ 用 QQ 号，抖音用 openid，内部各自标记；
- 记忆：共用一套长期记忆、日记本、小屋状态，两边说的话都算数；
- 分发：消息从哪来，回复就回哪去；
- 权限：抖音管理员看 openid 白名单，QQ 管理员沿用原配置，两套互不影响；
- 清洗：抖音消息会先去掉 @、`[表情]` 这类富文本和多余空行。

## 已知边界

- 抖音页面结构会变，选择器失效时点赞/评论可能失败，面板自检会给出哪一项不通；
- 首次登录如果卡在「验证码中间页」，点「扫码登录」用有头窗口手动过一次；
- 抖音私信里收到图片等非文本消息，会以 `[图片]` 占位告知，不会报错。
