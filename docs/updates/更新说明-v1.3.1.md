# PLUTO panel v1.3.1 更新说明

> 基准：v1.3.0 → v1.3.1　作者：Charon　日期：2026-10-29
> 原则：**只加能力，不动算法**。token 估算公式、压缩/承接流程、原版摘要模板、异常分支、备份与日志路径全部保持原样。

---

## 一、用户可见的变化

### 设置页（压缩承接）

- 新增三处灰色小字说明：自动压缩开关下方（解释请求内自动压缩不落库）、摘要字数上限下方（解释截断规则）、估算窗口下方（解释它只是基准，不改模型真实窗口）
- 数值输入增加前端校验：估算窗口 1,000–10,000,000、触发阈值 30–95、摘要字数 100–2,000、保留轮数 1–50；超出范围输入框立刻标红并回退到上一次有效值，不发出请求
- 备份份数、日志上限改为只读徽标展示（由插件常量决定，避免误改导致磁盘堆积）
- 自动压缩开关旁新增说明：请求内自动压缩只替换本次请求上下文，不持久修改会话

### 压缩日志

- 每条记录改为三行布局：类型徽标 + 时间 + 会话随机 ID；压缩前/压缩后估算 + 保留轮数；备份文件名 + 操作按钮
- 有备份文件的记录显示【查看备份】，弹窗展示文件名、大小、写入时间、消息条数与前若干条原文摘要
- 承接类记录显示【跳转到承接会话】，点击直接切到数据面板并定位、闪烁高亮该行
- 顶部新增下拉筛选：全部 / 手动压缩 / 手动承接 / 请求内自动压缩
- 备份写入失败的记录整行标红并显示「备份失败」

### 承接会话

- `/ctx_continue` 生成的新会话自动继承父会话的自定义备注与 AI 摘要（父会话数据不变）
- 会话列表里承接会话带「📌承接自:父会话」标签，点击跳到父会话
- `/ctx_sessions` 输出区分普通会话与承接派生会话，标明继承关系

### 增强摘要（可选，默认关闭）

- 关闭：完全走原版摘要提示词（约定 / 称呼 / 偏好 / 进度 / 情绪 / 梗）
- 开启：在原规则后追加「关键数据、配置项、代码要点」抽取要求，仍为要点短句，字数上限不变，禁止编造

### 指令返回

- `/ctx_compress`、`/ctx_continue` 结构化输出：操作类型、会话 ID、压缩前估算、压缩后估算、备份文件名；承接额外给新会话 ID 与 `/ctx_switch` 提示
- `/ctx_auto on|off [阈值]` 后回显开关状态、触发阈值、保留轮数、估算窗口

### 弹窗

- 【压缩上下文】二次确认补充风险提示（较早原文只剩摘要、可在日志里查看备份）
- 【生成承接摘要】二次确认补充行为说明（旧会话保留、切回方式、后续消息进新会话）

## 二、代码层变更说明

### `main.py`

| 位置 | 改动 |
| --- | --- |
| 顶部常量 | `PLUGIN_VERSION = "1.3.1"`；`CARRY_DEFAULTS` 增加 `enhanced_summary: False`；新增 `CARRY_LIMITS`（四组 min/max）、`CARRY_BACKUP_LIMIT = 20`、`ENHANCED_SUMMARY_EXTRA` |
| `_clamp_carry(value)`（新） | 服务端兜底校验，非法值回落到该键默认值，保证前端绕过时也不会写坏配置 |
| `_backup_history(...)` | 返回值由「文件名」改为 `(文件名, 错误信息)`；写完校验文件大小，失败返回错误文本；成功后调用老化清理 |
| `_prune_backups(dir)`（新） | 按 `st_mtime` 升序删除最旧文件，严格保留 20 份；删除异常只记调试日志 |
| `_summarize(..., enhanced=False)` | 仅当 `enhanced` 为真时在提示词末尾追加 `ENHANCED_SUMMARY_EXTRA`；默认路径与原版逐字一致 |
| `_set_parent / _get_parent`（新） | 在 `session_meta.json` 里记录 `parent_cid / parent_label`，读取时旧记录缺字段返回空串 |
| `_compress_core(...)` | 结构化回复文案；日志条目新增 `type / rounds_before / rounds_after / backup_ok / backup_error / new_cid`；备份失败时在回复里追加告警行 |
| `_continue_core(...)` | 新增父会话记录、备注与摘要继承、新会话 ID 回写日志；回复附 `/ctx_switch <前缀>` 提示 |
| `auto_compress(...)` | 日志类型写为「请求内自动压缩」（`kind = "auto"`），并带 `request_only: True`；行为与原版一致 |
| `cmd_ctx_auto` | 设置成功后回显四项当前配置 |
| `cmd_ctx_sessions` | 承接派生会话追加 `📌 承接自 <父前缀>` 标注 |
| `api_overview` | 会话项返回 `parent_cid / parent_label`；`carry` 载荷附带 `backup_limit / log_limit / limits` |
| `api_carry`（GET/POST） | 返回值补 `backup_limit / log_limit / limits`；写入前调用 `_clamp_carry` |
| `api_compress / api_continue` | 返回值补 `type / cid / before / after / backup / backup_ok / new_cid` 等结构化字段 |
| `api_backup_preview`（新） | `POST page/backup-preview`，校验文件名白名单与路径前缀后读取备份 JSON，返回大小、时间、条数与摘要条目 |
| `initialize` | 注册 `/backup-preview` 路由；其余路由与顺序不变 |

> 未改动：`est_tokens`（中文 0.6 / 其它 0.3 / 每条 +4，逐条取整）、`split_history`、`build_transcript`、原版 `SUMMARY_PROMPT`、`_compress_core` 的切分与写回顺序、`_continue_core` 的摘要构造方式、`compress_log.json` / `carry_backups` / `session_meta.json` 路径与结构。

## 四、升级方式

1. 覆盖插件目录（保留 `data/plugin_data/astrbot_plugin_token_panel/` 不动）
2. 后台「插件」→ 重载 `astrbot_plugin_token_panel`
3. 打开面板确认页脚为 `v1.3.1`

无需重置配置，无需重新登录。
