# 更新说明 · PLUTO panel v1.4.1

> 版本：1.4.0 → 1.4.1（2026-10-30）
> 插件标识：`astrbot_plugin_token_panel`（不变，配置直接复用）
> 作者：Charon

---

## 一、这次改了什么

一句话：**把「主动消息」做成插件内置能力，并把 7 个标签压成 3 个主页面 + 一个设置抽屉。**

### 1. 精细化主动消息（新增，默认关闭）

不是整点群发，而是按「有没有理由开口」决定：

| 判断点 | 规则 |
| --- | --- |
| 生效范围 | 仅主人私聊；群聊永不触发 |
| 参与条件 | 主人 12 小时内说过话才进入候选 |
| 静默期 | 主人发消息后先静默 180 秒（可调） |
| 情绪等级 | 0~5 级，决定最短间隔、每小时上限、每日上限、未回复上限 |
| 未回复惩罚 | 连续未回复达上限 → 等级 +1、冷却翻倍；主人回复后 24h 无惩罚 → 等级 -1 |
| 生成方式 | 模板档（本地随机）/ 自适应档（模型判断该不该发、给一句 ≤40 字内容） |
| 失败处理 | 模型超时、报错、空返回 → 自动回退模板档；绝不因为模型异常中断调度 |
| 反重复 | 与最近 15 条发言比对，相似度过高换一句 |
| 每日配额 | 默认 6 条，配额用完当天不再发 |

情绪等级默认值：

| 等级 | 最短间隔 | 每小时 | 每日 | 未回复上限 |
| --- | --- | --- | --- | --- |
| 0 热络 | 45 分钟 | 2 | 6 | 3 |
| 1 | 60 分钟 | 2 | 5 | 3 |
| 2 | 90 分钟 | 2 | 4 | 2 |
| 3 | 3 小时 | 1 | 3 | 2 |
| 4 | 5 小时 | 1 | 2 | 1 |
| 5 极克制 | 8 小时 | 1 | 2 | 1 |

> 与 `astrbot_plugin_proactive_chat` 功能重叠，同时开启会收到双份。装旧插件请先关掉。

### 2. 页面改版：3 主标签 + ⚙ 设置抽屉

| 位置 | 内容 |
| --- | --- |
| 上下文监控 | 会话列表、进度条、查看统计 / 压缩 / 承接 / 清空、清理闲置 |
| 搜索监控 | 今日搜索、成功率、平均耗时、关键词过滤与高亮、清空日志 |
| 抖音浏览 | 游客浏览状态、今日累计、立即浏览、最近浏览记录 |
| ⚙ 设置 | 行为 / 显示 / 主动消息 / 压缩承接 / 阈值与播报（原 7 个标签里的配置项与压缩日志全部在这里） |

### 3. 新增指令（3 条）

| 指令 | 权限 | 说明 |
| --- | --- | --- |
| `/proactive` | 管理员 | 开启 / 关闭主动消息 |
| `/proactive-status` | 所有人 | 开关、情绪等级、今日已发、下次窗口、最近一条 |
| `/proactive-reset` | 管理员 | 重置情绪等级、冷却、未回复次数 |

原有 18 条指令（`/token_*`、`/ctx*`、`/net_log`、`/dy_*`、`#标题`）名称、权限、行为**完全未变**。

## 四、升级步骤

1. 用新版覆盖插件目录（或插件市场更新）。
2. 后台「扩展功能 → 插件管理」点重载。
3. 打开面板 → 右上角 ⚙ → 「主动消息」分区，按需开启。
4. 想验证是否生效：`/proactive-status` 看状态，或等它在允许的窗口里发第一条。

## 五、已知限制

- 主动消息依赖 AstrBot 的会话切换能力发消息；目标会话被删除或 umo 变化时会跳过并记日志。
- 自适应档每次判断会消耗一次模型调用（关闭自适应档则完全本地、零调用）。
- 面板不再保留独立「预警设置」标签，阈值与播报参数在抽屉里。

## 六、补丁：上下文窗口上限来源修复（同日，版本号不变）

### 问题
面板把 `deepseek-flash` 的窗口上限显示成 `128000`，与模型真实窗口（元数据 `1,000,000`）不符，导致占比、剩余、预警全部失真。

### 根因
1. AstrBot 的本地模型元数据表里没有 `deepseek-flash`（会去 models.dev 拉取，渲染类请求经常拿不到），于是回落到了内置兜底值。
2. 更隐蔽的一层：AstrBot 在 Provider 未配置上限时，会把兜底值 `128000` 写回 **Provider 配置自身**。插件读 Provider 配置读到的 `128000` 是兜底复制品，不是用户配置，取上限时因此被“假值”顶住。

### 修复（只改取上限与展示，不动任何业务逻辑）
- 取上限改为四级：**手动填写 → Provider 的 `max_context_tokens`（跳过等于兜底值的假配置）→ 模型元数据 → 未设置**，按「每个会话实际使用的模型」分别解析。
- 兜底值不再写死，直接从 AstrBot 配置 `compression.fallback_max_tokens` 读取。
- 设置抽屉新增「上下文上限（手动兜底）」，`0` = 自动；并只读展示每个模型解析出的上限与来源。
- 百分比、剩余、预警、进度条颜色全部按解析后的上限重算；`/ctx` 与「查看统计」每次打开都重新解析，换模型后即时生效。
- 解析失败不再算成 `0%`，而是明确提示「获取模型上限失败」，不崩溃。

### 影响面
- 未改动：Token 估算公式、压缩 / 承接流程、备份与日志、抖音浏览、搜索监控、主动消息、全部指令与权限。
- 新增配置键：`limit_override`（默认 `0`，自动），其余配置沿用。
